Facility Location Problem

Several companies provide services to residents in a geographical area and together have numPF facilities (Preexisting Facilities). A new company wants to enter the market and plans to open numX new facilities. The locations for the new facilities must be selected from numCL possible locations (Candidate Locations) in order to attract as many customers as possible (to capture the largest possible market share).

The file demandPoints.dat contains data about 10,000 Lithuanian settlements (Demand Points): geographical coordinates and population. The existing numPF facilities are located in the largest cities, one in each city. New facilities may be built in the numCL largest cities. A new facility may be built in a city where another company's facility already exists, but only one new facility may be built in each city.

Customers select facilities based on geographical distance: all residents of one city select the nearest facility. Therefore, when evaluating a solution, the nearest existing facility and the nearest planned new facility are found for each city. If the shortest distance to a new company's facility is less than the distance to the nearest existing facility, all of that city's purchasing power goes to the new company. In the case of a tie, the new company receives one third of the city's customers.

The optimal solution is found using the Complete Enumeration algorithm: all possible combinations of locations for new facilities are generated, and the best one is selected.

The file flpenum.cpp contains the program code for finding optimal locations for new facilities. The main parameters (global variables) are:

  • numDP: size of the dataset used for the problem (number of cities, at most 10,000);
  • numPF: number of facilities already operating in the market;
  • numCL: number of possible locations for new facilities (the first points in the data array);
  • numX: number of new facilities.

At the beginning of the algorithm, a distance matrix is constructed. It stores the distances between points in kilometres, calculated using the Haversine formula. Since the distance from point A to point B is equal to the distance from point B to point A, only half of the matrix is filled. The distances stored in this matrix are used to find the optimal locations for new facilities.

Laboratory Work #1

Algorithm Analysis

  • Choose the dataset size (parameter numDP) so that distance matrix calculation takes 3–5 seconds, and choose the number of possible locations (parameter numCL) so that solution search takes 15–30 seconds. Use the computing resources of uosis.mif.vu.lt.

  • Considering data loading and distance matrix calculation as the sequential part of the algorithm, and solution search as the parallelizable part, estimate the theoretically possible speedup of the algorithm using 2 and 4 processors, as well as the maximum possible speedup (based on Amdahl's law).

Development of a Shared-Memory Parallel Algorithm

  • Considering data loading and distance matrix calculation as the sequential part of the algorithm, develop a shared-memory parallel algorithm and experimentally investigate its speedup using 2 and 4 processors. In one graph, show:

    • linear speedup;
    • experimentally determined speedup of the parallelized part of the algorithm;
    • experimentally determined speedup of the entire algorithm.

  • Develop a shared-memory parallel algorithm for distance matrix calculation and experimentally investigate its speedup using 2 and 4 processors. In one graph, show:

    • linear speedup;
    • experimentally determined speedup of distance matrix calculation;
    • experimentally determined speedup of solution search;
    • experimentally determined speedup of the entire algorithm (when distance matrix calculation and solution search are parallelized).

  • In one graph, show linear speedup and the experimentally determined speedups of distance matrix calculation, solution calculation, and the entire algorithm (when both distance matrix calculation and solution search are parallelized), as functions of the number of processors.
